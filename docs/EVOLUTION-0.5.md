# Soul 0.5 进化流程与边界

本版自动改进的是项目技能与工作策略。用户注册固定任务与验收规则之后，模型可以提出候选、执行独立试验、组合方案、继续递归，并自动采用通过验证的方法。模型不能更换验收条件、开启任意工具、修改用户偏好或插件核心源码。

## 一次运行

1. 读取同项目、同套件当前已采用的技能；没有可用版本时读取 seed。
2. 执行所有 train 用例，得到基线。结果来自真实内存读写或容器运行，不接受模型自报 pass、耗时或得分。
3. 编辑模型生成多个候选技能。去除本轮运行中出现过的相同策略；无新候选则结束。
4. 在独立状态中并发执行候选。所有策略使用相同任务、检查和配置。
5. 编辑模型看到训练输入、实际行为摘要和检查通过情况，组合一个新方法；组合方法必须再次执行，不能凭编辑模型自评直接获胜。
6. 从当前方法、候选和组合方法中选择有改善且无已通过用例回退的方法。有改善才进入下一轮；下一轮使用上一轮胜者及经验。
7. 最终方法选定后，运行 baseline 与 selected 的 validation 用例。这些输入与结果不会反馈给编辑模型；固定 expected 从不发送给模型，也不进入代码容器。
8. 只有训练和验证用例全部通过，且相对基线存在质量或步骤改善，才写入 active 技能并停用上一版。否则保留旧版。

质量提升首先看完整通过的用例数，并阻止逐用例通过状态回退。质量相同时，至少两个用例减少模型请求或动作数，其他用例不得增加请求、动作或工具错误。耗时记录供查看，不能单凭一次更快升级。

训练中出现局部改进仍可继续递归，但局部改进不能自动发布。组合失败时可保留更好的候选；执行中基础设施失败、请求超时、预算不足、来源变化都会停止，不能把缺失结果算成功。没有提升、候选重复、达到轮数或需预留验证额度时停止扩展。

## 套件格式

完整样例位于安装包中的 `examples/evolution-memory.json` 和 `examples/evolution-javascript.json`。可运行 `/learn evolve example memory` 或 `javascript` 复制到当前项目的 `.dsh-soul` 目录，不覆盖已有文件。

```json
{
  "version": 1,
  "id": "my-task-family",
  "title": "这类任务的目标",
  "keywords": ["匹配当前任务的词"],
  "runtime": "memory",
  "auto": false,
  "seed": {
    "title": "初始方法",
    "preconditions": ["适用前提"],
    "steps": ["执行步骤"],
    "checks": ["检查内容"],
    "counterexamples": ["不适用情况"]
  },
  "cases": [
    {
      "id": "example",
      "split": "train",
      "input": "任务说明",
      "files": {"input.txt":"给模型处理的材料"},
      "checks": [{"target":"answer","kind":"equals","expected":"预先固定的结果"}]
    }
  ]
}
```

上面只展示一个用例的格式，注册时实际需要 4–12 个用例，train 和 validation 各至少两个，不能复制同一输入凑数。每个用例最多 12 条检查。`keywords` 最多 8 个；套件总长最多 256 KB。

支持的检查：

| target | 检查对象 |
| --- | --- |
| answer | finish 的真实最终答案 |
| file + path | 内存工作区的真实文件内容 |
| execution | JavaScript 容器实际输出，仅用于 javascript |

`equals` 比较去掉首尾空白后的文本；`jsonEquals` 解析 JSON 后深度比较；`contains` 检查指定文本是否存在。没有动态正则或任意验证脚本执行入口。代码套件至少需要一项 execution 检查，不能只检查模型说“完成”。

JavaScript 用例额外包含 `invocation`，是容器调用默认导出函数时使用的 JSON 参数。它不包含 expected，编辑模型也看不到该参数。任务说明应描述通用函数约束，避免在说明里硬编码验收答案。生成文件固定入口为 `solution.mjs`；可引用同一只读工作区里的其他模块。

当前不支持依赖网络的任务、任意 shell 项目、浏览器操作或自动部署。内存和函数执行器只覆盖可描述为有限输入与确定性检查的任务；开放式设计、复杂工程交付等仍应使用正常 DSH 工作流及人工判断。

## 自动运行与采用权限

插件配置 `evolution: true` 后，用户必须先用 `/learn evolve register 文件路径` 注册本项目套件。工具 `learning_evolve` 只能启动已注册套件，不能提交新验收规则、路径或执行命令。

套件 `auto: true` 开启失败触发：同一轮至少两次非 Soul 工具错误，用户当前任务包含套件关键词，且冷却时间已到时，排队等待观察到的宿主空闲。当前队列最多 16 个项目条目，近邻重复触发合并；进程退出不重放队列。手动 run 和模型显式调用可以跳过自动冷却，但仍受持久化额度限制。

自动验证和人工反馈是两条不同证据通道。套件通过可以自动采用项目技能，卡片包含 `verification.kind: fixed_suite`；它不会增加人工通过会话数。普通生成的技能候选仍按原人工试用规则处理。自动技能收到正面人工反馈不会因此降回 trial，收到 fail 则立即停用。

回退命令停用当前自动版本并加入遗忘指纹；前版仍存在、没有失败记录且验证合同未变时可恢复前版。更换套件内容会使原自动版本失效，下一次从新 seed 开始。注销套件会清理它的技能与试验正文；不会删除原始套件文件和宿主聊天记录。

## 执行隔离

memory 执行器只有 read/write/finish 三类动作。每个策略、每个用例都有独立 Map，不会共享写入；动作中的路径只接受有限的相对路径，禁止 `..`、绝对路径和 Windows 驱动器路径。最多 32 个文件、每文件 16000 字节、工作区总长 64000 字节；输出动作和每用例请求次数也有上限。没有宿主 ToolRuntime 或 shell 桥接。

javascript 先验证本地 Docker endpoint 与预先存在的 Linux 镜像，再请求模型。镜像解析为内容 ID，创建容器使用 pull=never。仅挂载此次生成的临时文件，且为只读；不会挂载项目目录、Docker socket 或用户凭据。禁网络、只读根文件系统、非 root 用户、删除 Linux capabilities、no-new-privileges，并限制 CPU、128 MiB 内存、64 进程、输出和时间。

函数在容器内的工作线程执行，外层计时器与宿主超时都可以终止意外死循环。宿主按随机精确容器名清理并等待结果，不使用宽泛的全局删除。容器非正常退出、OOM、超时或错误输出不能通过验收。异常断电或 Docker 失联可能留下容器，需按 Docker 的管理方式检查 `dsh-soul=probe` 标签；隔离依赖本地 Docker 与内核，不承诺防御所有恶意代码漏洞。

## 持久化与并发

schema 4 新增套件、运行、请求额度、探测记录、版本与依赖关系。运行状态为 running、adopted、unchanged、rejected、failed 或 interrupted。单 profile 同时只有一个进化任务；任务内部并发有界。数据库事务在请求发出前预留额度，失败/取消也计数，不会重启后清零。

请求有独立超时，任务有总时间上限；非协作的供应商可能仍在后台完成已收到的请求，插件不会继续等待或采用迟到结果，也不会自动重发。跨进程通过运行租约避免同时工作，过期运行标为 interrupted；不自动恢复付费步骤。

删除或修订使来源 epoch 变化时停止采用；由旧技能派生的实验记录建立依赖。遗忘会清理相关 probe 正文与结果摘要。套件中用户主动提供的 fixtures 独立保存，需 unregister 才从插件中移除。usage 只存可识别的非负计数字段，未报告的用量为未知。

## 与 Harness² 的关系

参考官方仓库 https://github.com/google-research/harness2 的 `harness2/core/recursion.py`、`library.py` 和 README。核对日期 2026-10-26，版本 `1cfe254e8d25b15f37048c3730134686abe60335`；论文 https://arxiv.org/abs/2610.14224 。

移植的是设计原则：同任务的执行对比、提出与组合后的独立探测、沿上一轮方法继续递归，以及保留适用条件、经验和证据供未来任务使用。代码独立编写，没有复制上游源码。

与上游的区别：本版自动采用依赖固定验收，不复现它不依赖真实答案的开放任务反馈方案；编辑面限于结构化技能，不包含任意系统提示、工具权限、子代理配置和插件源码。执行后端是自有内存/JavaScript 容器执行器，不是上游全套后端。

固定验证集在多次进化中会被重复使用，不能当作永远独立的泛化测试。contains 等弱检查可能被满足却漏掉任务的重要要求；验证规则、样本覆盖和实际任务回归仍需维护。现有离线 demo、宿主协议测试和容器测试证明流程可运行，没有建立真实模型在开放任务上的成功率提升、净提速或费用下降结论。
