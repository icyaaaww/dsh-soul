# 0.5.1 审查修复验证

日期：2026-10-26。未调用付费模型，未修改日常 profile。

本地 Windows / Node 24.19.0，分别指定 DSH 0.2.0-rc.2 与 0.2.1-rc.2 运行 `npm run check`，每次 95 项测试：93 通过、0 失败、2 项真实 Docker 测试跳过（本机无 Docker）。11 个检索场景通过。CI 的独立 Linux Docker 作业实际执行这两项，缺少配置引擎时失败。

`check` 现在包含自动迁移测试：校验仓库内旧发布包 SHA-256，再使用旧版代码建库，验证 0.1.0 / 0.2.1 / 0.3.0 / 0.5.0 的 schema 1/2/3/4 → 5。0.5.0 fixture 运行旧引擎生成真实自动 active 技能，升级后检查其变为 candidate 且不再注入提示。历史包仅作开发测试，不进入安装 TGZ。

关键回归：

- 固定套件通过产生 candidate，接受后为 trial，同一人工会话重复 pass 不累计；两个不同会话才 active。
- 模型工具只返回预估，真实宿主命令才启动执行；旧自动接口不调用模型。
- 待审核结果阻止重复付费；回退后重生同一指纹报告 blocked_strategy。
- 并发前原子预留输入字节，不超过单次或每日额度；执行 trace 合并读取、写入只回传摘要。
- 24 个匹配技能的 discover 实际执行 5 次 SQL prepare；不再按每条技能重复查询 summary。此项证明查询数下降，不证明用户能感知的毫秒收益。
- 清理失败保留超时/取消主因，并阻止结果发布；重复修订事务拒绝，不改变原记忆和事件数。
- 未知 profile 布局拒绝共享回落；显式 profile 的数据库路径互相隔离。
- pre-step 和持久事件共享过滤；pre-step 不产生可引用来源、不沿用前一消息的来源；拒绝输入及子代理不进入召回。
- 真实新宿主版本检查验证 semver 区间含后续 0.2.x RC/正式版，拒绝 0.3 及更早未支持版本。这是版本门槛测试，不是对未来宿主行为的兼容性实测。

本次改动收紧了权限和声明，没有把固定验证变成泛化证明。完整仓库编码执行、动态/新鲜评测样本和真实模型成功率测量仍未实现。
